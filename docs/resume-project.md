## 一、简短描述

### 1. 一句话版（简历项目名旁 / 列表项）

> 智能图片管理平台，集成 AI Agent、语义检索与多人协同编辑（Java + Python + Vue）

### 2. 简介版（约 60 字，可用于简历项目标题下方）

> 面向团队协作的图片管理系统，支持图片上传存储、在线裁剪处理与分空间权限管理，
> 并集成 AI 能力：自然语言驱动的智能助手、以文搜图的语义检索、多模态自动标注，
> 以及多人实时协同编辑。

### 3. 自我介绍版（约 200 字，用于面试开场）

> Smart Picture 是一个图片管理平台，定位是"把 AI 能力嵌进日常的图片管理流程"。
> 整体是 Java + Python 双语言架构：Java 后端负责业务、存储、权限与协同编辑；
> Python 侧负责 AI —— 包括一个基于 LangGraph 的智能助手（11 个工具，可以用自然语言
> 完成找图、上传、建相册、生成 PDF 等操作）、向量语义检索，以及基于多模态模型的
> 图片自动标注。前端是 Vue 3，支持在线裁剪旋转和多人协同编辑。
>
> 我主要做三件事：一是 **Agent 工程化**，把业务上下文纳入图状态，让工具可独立测试；
> 二是 **AI 能力落地**，包括语义检索的效果调优和长期记忆的多用户隔离；
> 三是 **并发与稳定性治理**，做了缓存一致性、限流与压测验证。

## 三、简历正文（推荐版）

> **Smart Picture 智能图片管理平台**（个人项目｜2026.XX - 2026.XX）
>
> 多语言架构的图片管理系统：Java 后端负责业务与存储，Python 侧提供 AI Agent、
> 向量检索与多模态能力，前端支持在线编辑与多人协同。

**核心工作：**

**1. AI Agent 与工具编排（LangGraph）**
基于 LangGraph StateGraph 构建可调用 **11 个工具**的智能助手（图库搜索/上传/删除、
相册管理、PDF 生成、图片分析、长期记忆）。将 token、搜索上下文等业务字段纳入图状态，
工具通过 `InjectedState` 读取、`Command` 回写，实现工具无状态化与可独立测试，
支持多轮工具调用循环。

**2. 跨会话长期记忆与多用户隔离**
基于 Chroma 向量库实现长期记忆存储与语义召回，按 `userId` 强制过滤实现多用户数据隔离，
无法确定用户身份时 fail-closed 拒绝读写；高相似记忆自动去重合并。记忆提取由
**独立线程池**异步执行，并以"时间 + 轮数"双条件节流控制 LLM 调用成本。

**3. 语义检索**
实现"向量召回 + 关键词兜底"双通道图片检索，向量服务不可用时自动降级为 LIKE 查询
保障可用性。基于真实数据分布**标定相似度阈值**（相关 0.51~0.61、噪声 0.40~0.47，
取 0.48），保证查准率与查全率的平衡。

**4. 多人协同图片编辑**
基于 WebSocket 房间模型 + **Disruptor 单线程消费**保证消息串行有序，实现编辑权抢占、
观看模式与画布实时同步（旋转/缩放/裁切框）；新成员加入时下发操作历史回放追平状态。

**5. 数据一致性与跨端正确性**
Caffeine + Redis 两级缓存，通过版本号失效保证多实例一致性、TTL 抖动规避雪崩、
单飞（single-flight）防止击穿。统一 REST 与 WebSocket 两条链路的 JSON 序列化口径，
雪花 ID 以字符串形式下发，规避 JS 安全整数上限（2^53）导致的精度丢失。

**6. 工程化与并发治理**
将 4 个服务整理为分层结构（app/services/common/data），补齐依赖清单与配置模板，
路径锚定到文件位置，保证任意工作目录下可正常启动。针对并发瓶颈实施限流
（429 + Retry-After）、读超时分离与过载降级，并通过压测脚本量化验证性能表现。

> 版面紧张时，第 5、6 条可合并为一条，或砍掉第 6 条。

## 五、面试追问预演

简历上写了，面试官就会顺着问。以下每条都必须能答上来，答不上来反而扣分。

| 简历点 | 会问什么 | 答案要点 |
|---|---|---|
| **业务字段进图状态** | 为什么要把业务字段放进图状态？ | 全局字典方案下工具无法单测、LLM 并行调工具会互相踩数据；可延伸讲**注入参数不能带默认值否则会泄漏给模型**、**字段缺失会抛 KeyError** 这两个实测踩到的坑 |
| **记忆隔离** | 为什么拿不到身份要拒绝读写，而不是不过滤？ | fail-closed：数据串号比功能缺失严重得多。属加分回答 |
| **记忆提取异步化** | 异步会不会读不到刚说的信息？ | 不会——同一会话的原文就在短期记忆里。要能说清"短期记忆 vs 长期记忆"的区别 |
| **相似度阈值 0.48** | 这个数怎么来的？ | 实测分布断层清晰（相关 0.51~0.61 / 噪声 0.40~0.47）。**能说出"我实测过"比数字本身重要** |
| **Disruptor** | 为什么单线程消费？会不会成瓶颈？ | 串行保证有序、避免并发写同一连接；单线程处理内存级事件足够，瓶颈在 IO 不在 CPU |
| **缓存三项机制** | TTL 抖动解决什么？ | 版本号→一致性、抖动→雪崩、单飞→击穿，三个要能一一对应 |
| **雪花 ID 字符串下发** | 为什么要转成字符串？ | 19 位超出 2^53，JS 会四舍五入；REST 与 WebSocket 必须口径一致 |

**适合主动讲的两个技术点**：

1. **雪花 ID 精度** —— 跨协议不一致，排查过程有戏剧性
2. **语义检索阈值** —— 有实测数据支撑

面试官喜欢"发现问题 → 定位根因 → 量化验证"的完整链条。
